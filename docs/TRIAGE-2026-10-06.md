## Follow-up fix: checked Android save and ghost writes

After the simulator/corpus pass, Chris asked for another concrete issue to
try. The 26 open issues have no newer symptom/log updates than the reviewed
#390 acknowledgment. Controlled storage failures uncovered an additional
Android save/ghost import bug. This is a new local reproduction, not reporter
confirmation or a diagnosis of #234's console-identity mismatch.

`AtomicFile.finishWrite` can log a failed sync or rename and return normally
([Android framework implementation](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-cts-12.0_r3/core/java/android/util/AtomicFile.java)).
The rating-restoration path already checks publication; `KartPadSaveStorage`
did not. A silent staging failure could report success without a pending
request. A silent backup failure could allow the active save to change without
the promised backup. A silent active-save replacement failure could discard
the pending import even though it was never applied.

The bounded correction keeps the existing file format and restore flow:

- Check file sync before finishing an atomic write, then verify the final bytes
  and absence of unfinished `.new` / `.bak` files.
- Check staging/backup directory and completed-rename syncs. Do not proceed past
  a failed backup or discard a request after a failed replacement.
- On a ghost retry that already contains the requested slot, repeat the active
  directory sync before clearing the request. Otherwise a previous failed
  directory sync could be bypassed by the no-rewrite path.
