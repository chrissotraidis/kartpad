KartPad 0.8.11 (build 276) makes Android menus with movie thumbnails keep up, fixes Wii Remote extensions and the Wii Remote player slot on Mac, and brings the iPhone/iPad touch-control and screen fixes merged since 0.8.10.

### Fixed

- **Menus that stayed slow (Android):** the main menu, the single-player menus and the online menu between races play small movies, which the game decodes on a background thread. KartPad ran that thread until it finished each movie frame, even when the game's main thread was due, so after any hitch the menu could stay well below 60 FPS. The movie decoder now steps aside for the main thread, as it does on a Wii. On a slowed-down emulator the main menu went from 27–43 FPS to 59.5–60 ([#554](https://github.com/chrissotraidis/kartpad/issues/554), [#339](https://github.com/chrissotraidis/kartpad/issues/339)). It doesn't yet explain the slow Retro WFC room screen in #554.
- **Two timing faults while online (Android):** when one of the game's short-lived background threads finished, as happens while signing in to Retro WFC, KartPad handed control to the game's main thread even if that thread was meant to be sleeping, and its sleeps then did nothing until it next waited on something. Separately, the short sleep the game takes once per frame online took 1.6–1.7 ms instead of the 0.5 ms it asked for; it now takes about 0.76 ms, which gives back roughly a millisecond of each 16.7 ms frame. Both were measured on an emulator only. Neither is shown to explain the 40–100 ms frames on the Retro WFC room screen, and no slow phone has run them yet ([#554](https://github.com/chrissotraidis/kartpad/issues/554)).
- **Wii Remote extensions and the Classic Controller D-pad (Mac):** 0.8.7 listed fixes for these, but a build setting kept KartPad's Wii Remote fixes out of every Mac build. Plugging in a Nunchuk or Classic Controller made the remote disappear until KartPad restarted, and the Classic Controller D-pad did nothing. Mac builds now include them, so the remote should stay connected and change type when an extension goes in or comes out, with a working D-pad, steadier Classic Controller sticks and calibrated motion. Nobody has tried this with a real remote yet; if you have one, please say how it goes ([#476](https://github.com/chrissotraidis/kartpad/issues/476), [#306](https://github.com/chrissotraidis/kartpad/issues/306)).
- **A Wii Remote that came up Unassigned (Mac):** macOS gives a remote a new identity on every connection, so the Player 1 slot saved for it could stop matching, and the game ignored it until you picked Player 1 in Controller Settings. If Player 1's saved controller isn't connected, the first controller without a saved slot now plays as Player 1. Your saved choice doesn't change, and a Player 1 set to no controller stays that way ([#476](https://github.com/chrissotraidis/kartpad/issues/476)).
- **Getting touch controls back (iPhone/iPad):** when a controller hides the touch controls, **Show Touch Controls** is now the first row of the ••• menu, and **Controls → Auto-hide Touch Controls with Controller** turns the behaviour off. Only a controller on Player 1 hides them; a pad on Player 2–4 doesn't ([#567](https://github.com/chrissotraidis/kartpad/pull/567)).
- **Rotation and external displays (iPhone/iPad):** the game follows the screen's orientation through rotations on iPadOS 27, and leaves an external display to the system for mirroring ([#568](https://github.com/chrissotraidis/kartpad/pull/568)).

### Changed

- **Snapdragon phones (Android):** missing or broken characters on Snapdragon phones come from Qualcomm's 512.762 driver, and a Turnip driver fixes them ([#104](https://github.com/chrissotraidis/kartpad/issues/104)). On those phones the **GPU Driver** row now says "Phone's driver. Add Turnip here if characters are missing." and **Graphics Diagnostics** says to try GPU Driver first.
- **Diagnostic logs (Android):** health lines include the battery's remaining charge in µAh (`battery_charge_uah`), which shows power use over a few races far better than the percentage ([#339](https://github.com/chrissotraidis/kartpad/issues/339)).
- **Diagnostic logs name the busy thread (Android):** each performance line is followed by a `KartPadSched` line that splits the time between the game's main thread, its other threads (naming the busiest), idle time, the main thread's sleeps and network waits. A log saved on a slow online screen now shows which thread took the time ([#554](https://github.com/chrissotraidis/kartpad/issues/554)).

### Updating

- **Android:** install the new APK over 0.8.10, or use **Update available → Update Now**. Don't uninstall first. Your game data, saves, Retro Rewind and ghosts stay.
- **iPhone, iPad and Mac:** build 0.8.11 with PadMint, then replace only the app. Your data stays.
