# KartPad 0.4.25 diagnostics preview 2

Android code 119 and iPhone/iPad build 51 are available for people with an existing crash, slowdown or graphics issue. This update collects better evidence from your normal attempt to use the game. It is not a confirmed fix for those issues.

## Try your existing problem once

1. Update over your existing app, keeping your game data and saves. Android users should use the Community Release APK. If Android rejects the signature, stop and report that message rather than uninstalling. On iOS, re-sign the unsigned IPA with the same identity/bundle setup you already use.
2. Reproduce the action that normally fails. Note Original or Retro, the course/menu/transition and approximately when it happened. If it closes, reopen the app to export the earlier attempt. You do not need to intentionally crash the app or use the developer crash-test action.
3. Android: open **Help → Report a Problem → Save Diagnostic Log…** and choose the failed game session. If startup failed before a session exists, export the available OS evidence from the launcher. iOS: open **Report a Problem…**, fill in the short form and use **Save or Share Report…** to save the `.log` file.
4. Review the text and attach it to your existing issue, with your device model, OS version and build number. For broken graphics, include one screenshot from the same scene. Nothing uploads automatically. Do not attach game images, saves, console identity, or a full private diagnostic archive unless specifically requested.

If export itself fails, reply with what you see. A missing OS crash report is not your fault, and sending the same old log repeatedly is not necessary.

## What is new

- Native crash collection is no longer bypassed by the mobile abort handler. Exact Android BuildIDs and Apple symbols are retained by the maintainer.
- Android reports include bounded OS exit information, available native stack summaries and thermal/power/memory history, including startup failures without a game session.
- iOS reports include recent native session logs and available Apple system diagnostics, plus independent memory/thermal samples.
- Shared startup records distinguish graphics instance, adapter, device, surface and guest-entry failures. Dawn instance messages are captured; an unusable mobile Null fallback is rejected early.
- Matching coarse frame windows, selected-function CPU/wall timings and sampled graphics-input checks provide context for performance and corrupted characters.

This preview enables additional renderer checks and selected-function timing. They can affect performance, so its FPS should not be treated as a clean performance comparison with the normal release. These samples do not cover every function or every draw. Android is optimized/non-debuggable, with shell profiling enabled for deeper follow-up when needed.

Both platform builds, package audits, bounded-export tests and native-symbol identity checks passed. The preview has not been physically validated on the maintainer's devices or the affected phones. Reporter testing is the next step; no physical crash test by the maintainer is a release prerequisite for this preview.

The iOS package displays version **0.4.25 / build 51**; Android displays **0.4.25-diagnostics.2 / code 119**. The normal 0.4.24 releases remain available. Keep saves backed up; do not uninstall to switch builds. Downgrading Android across version codes may be blocked.
