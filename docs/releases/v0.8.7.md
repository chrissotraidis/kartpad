KartPad 0.8.7 (build 272) makes the Android WiiCompiled 0.9 (Beta) graphics engine much faster, fixes iPhone and iPad builds that couldn't start the game on some self-signed installs, and adds a Disable Bloom setting on Android, iPhone and iPad. Retro Rewind stays at 6.13.4.

### New

- **Disable Bloom (Android, iPhone, iPad):** **⋯ → Display → Disable Bloom** removes the glow around bright areas. It takes effect when the next scene loads and stays set after restarting. Bloom stays on by default. The Mac already has it under **KartPad → Settings… → Graphics** ([#535](https://github.com/chrissotraidis/kartpad/issues/535)).

### Fixed

- **Android, WiiCompiled 0.9 (Beta) engine much slower than Classic:** the beta locked its game, graphics-command and render threads onto a single CPU core, so they took turns on it while the rest of the phone sat idle. It now leaves thread placement to Android. KartPad also told Android that frames took less time than they did, so Android kept the CPU cores slow. It now reports each frame's real duration and includes the beta's helper threads. On a Pixel 9 Pro XL, a Luigi Circuit race went from about 20 FPS on 0.8.6's beta to a steady 60 FPS at 3× render resolution. Classic stays at 60 on that phone, with slightly higher clocks.
- **iPhone and iPad, "mmap iOS flat guest reservation failed" before the game starts:** KartPad reserved 4 GiB of address space for the Wii's memory layout, more than iOS gives apps you sign yourself. It now reserves only what the layout uses, about 3.5 GiB ([#530](https://github.com/chrissotraidis/kartpad/issues/530)).
- **Error 61070 from a mistyped server setting:** **Experimental Server Settings** (Private Wii Server… on Mac) now refuses Retro WFC and Nintendo addresses. Entering Retro WFC's address there sent every online request to the wrong place; Retro Rewind connects to Retro WFC on its own ([#520](https://github.com/chrissotraidis/kartpad/issues/520)).
- **Android, changing Render Resolution in the beta engine** during a game now takes effect.
- **Android, importing a game ZIP with too little free space** now says the device is out of storage, instead of calling the archive damaged.
- **Mac, Classic Controller Pro D-pad:** directions now register ([#306](https://github.com/chrissotraidis/kartpad/issues/306)).
- **Mac, Wii Remote player slot:** attaching a Nunchuk or Classic Controller no longer loses the remote's saved player slot. Problem reports now say whether the Mac sees the remote, recognises it as a controller and has it open. A Nunchuk or Classic Controller that isn't detected at all is still open ([#476](https://github.com/chrissotraidis/kartpad/issues/476)).
- **Character models:** the Classic engine on Android, iPhone, iPad and Apple TV now ignores two unused bits when choosing a character's bone matrix, as the Wii does. This doesn't fix the missing characters on Snapdragon phones ([#104](https://github.com/chrissotraidis/kartpad/issues/104)).
- **PadMint builds stopping at `CERTIFICATE_VERIFY_FAILED`** now say how to fix it: start PadMint with **PadMint.command**, or install the certificates for a Python from python.org ([#532](https://github.com/chrissotraidis/kartpad/issues/532)).
- **Mac app icon** now uses the current KartPad logo.

### Updating

- **Android:** install the new APK over 0.8.6. Saves, settings and game data stay.
- **iPhone, iPad and Mac:** start a new build in PadMint and install it the same way as before. Your saves and game data stay.

### Checks

- **Pixel 9 Pro XL (Android 17):** the beta-engine fixes were measured on the phone from the 29 October integrated source with each change applied. With both fixes, a Luigi Circuit race at 3× held 59–60 FPS (median 59.9), against 48–58 (median 52.3) before the second fix. A Retro Rewind race on 3DS DK Jungle at 4× held 55–61 FPS with the first fix. Classic stayed at 60 FPS. The owner played the fixed build and found it smooth.
- **iPad Pro 12.9-inch (6th generation):** a PadMint personal build of the #530 fix, signed without any special entitlement, started Mario Kart Wii and held 60 FPS on the title screen. That iPad may never have hit #530, so this shows no regression, not the fix on an affected device.
- **PadMint player check (iOS):** passed for the #530 commit from current PadMint `main`, with Apple's Python 3.9.6 and an empty PadMint folder.
- **Pending before publishing:** the release build from this commit, the PadMint player check on it for iOS and Mac, Android update-in-place over 0.8.6, and Disable Bloom on a live iPhone or iPad.
- **Not checked:** other Android phones (Snapdragon, MediaTek, Exynos), the beta at 4× with both fixes, a physical Classic Controller Pro or Nunchuk on Mac, and an iPad with 3 GB of memory like the #530 reporter's.
