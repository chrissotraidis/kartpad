KartPad 0.8.2 (build 264) fixes Mac build retries, keyboard settings and a Retro Rewind race-start crash.

### Fixed

- **PadMint on Mac:** repeated **Make my copy** builds reuse verified files and keep earlier app/ZIP outputs. Setup instructions use **Mario Kart Wii → This Mac**, explain opening a newly extracted PadMint folder and cover Rosetta. The companion PadMint update restarts natively on Apple Silicon; Intel Macs retain supported mobile builds, not the Mac game target.
- **Mac keyboard:** reset restores defaults instead of clearing them; remaps and clears save immediately and reach the game's Classic input. Shift, Control and Option can be captured; Command shortcuts stay reserved.
- **Retro Rewind:** skip a malformed model texture link that caused a fatal memory access when entering a race, while preserving valid links and texture names.

### Updating

Build 0.8.2 with the latest [PadMint](https://github.com/chrissotraidis/padmint/releases/latest). Mac players choose **Mario Kart Wii → This Mac** on Apple Silicon, then import their existing game data. [Mac instructions](../INSTALL_MACOS.md) include reusing PadMint's prepared files. Keep existing saves, game files and caches. Android continues using its APK; iPhone/iPad use PadMint's game-code-free input, not a directly installable release IPA.

### Checked and remaining limits

The implementation passed six CI checks, including native Apple Silicon/Intel fixtures, and a full packaged Mac build and downloaded-package audit. Original completed a race; both games accepted remapped Item input and reopened with licenses and imports retained. Keyboard autosave and explicit Save Profile persisted. Retro entered races past the former fault, quit normally and reopened; owner data stayed unchanged.

A full Retro race was not completed. Selecting 100cc displayed a 200cc intro twice; this remains unresolved. Physical modifier capture and reset-default persistence after relaunch remain unverified; synthetic modifier coverage passed. Audio quality and the reported high-FPS regression are unverified. No FPS improvement is claimed. The accepted scope for this focused release requires race entry, input and quit/reopen, not full-race completion. Final release artifacts still require their normal build/audit and PadMint player-check gates.
