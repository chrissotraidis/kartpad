# Android persistent issues (excluding the Adreno character-geometry bug)

Date: 2026-09-26. Scope: open issues on chrissotraidis/kartpad, read with comments, plus every attached log and diagnostic ZIP (saved under `work/issue-triage-20260926/`, which is not committed). Branch state: root `codex/release-051-20260925`, Android runtime `codex/android-input-menu-20260926`, compared against the public `v0.5.0` tag (code135).

#309, #310 and #322 are iPad reports and are left out. #120's texture problem and the invisible bodies in #216, #301 and #323 belong to the geometry bug and are also left out.

## Summary

Startup exits are really four problems with different causes. Two are understood: the missing Vulkan debug-function lookup was fixed in 0.5.0 and confirmed by three reporters, and the Adreno 740 overlay debug-label crash is fixed on this branch but not yet released. One is understood but not fixed: the PowerVR BXM-8-256 fails a Dawn capability check. The fourth is a group of older reports that have no log, so there is nothing to diagnose them from.

The Grand Prix end crash has no Android log at all. Upstream's PC crash record shows a guest OS panic, `ARCInitHandle: bad archive format`, while `RaceScene` builds the award ceremony UI. Our crash file would record the same stack but could not say which archive was bad. That is now logged.

Online has two unrelated problems. On the Pixel 8 Pro, the menus stall and then disconnect, and turning off Retro music mostly fixes it. On the Galaxy S24, mobile data fails with `86420` while Wi‑Fi or a VPN works, which points at carrier NAT.

Low-end performance is CPU-bound on the main thread. Two lower-end phones also show the OS killing the app for low memory.

## Changes made (committed locally, not pushed)

Runtime commit `5486906` on `vendor/runtimes/android` branch `codex/android-input-menu-20260926`:

- `runtime/src/hle/storage/dvd.cpp`: keeps the last eight distinct virtual disc paths read (for example `/Scene/UI/Award_E.szs`). Streamed music moves to the end of the list instead of pushing archives out. Host paths are never recorded. The list is read with `try_lock`, so a crash in the middle of a read cannot deadlock the crash writer. The console also gets one line per menu scene (`[dvd] scene archive …`) and per course (`[dvd] course archive …`), deduplicated.
- `runtime/src/main.cpp`: every `crash_*.txt` now includes `[runtime] recent DVD reads (oldest first): …`.
- `aurora-main/lib/window.cpp`: logs "App entered background" and "App returned to foreground" once per transition.

Root repo, `android/app/src/main/java/dev/kartpad/android/KartPadRuntimeHealth.kt`: each 10 s health sample adds `device_ram_mib`, `available_ram_mib`, `system_low_memory` and `network` (`wifi`, `cellular`, `vpn`, `ethernet`, combinations, `none` or `unknown`). It records only the transport type, never addresses, SSIDs or carriers, and uses the existing `ACCESS_NETWORK_STATE` permission.

Verification: `dvd.cpp` and `window.cpp` pass a syntax-only compile with the Android build's flags. `main.cpp` shows the same two unrelated `NetworkHle` errors as the unmodified file under those borrowed flags. `./gradlew :app:compileReleaseKotlin` passes. No APK was built or installed, and no device was touched. The root repo's submodule pointer was not bumped, because another agent is pinning runtimes on this branch and has uncommitted GX work in the runtime submodule.
